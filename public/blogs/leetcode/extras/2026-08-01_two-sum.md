## 题目描述

给定一个整数数组 `nums` 和一个整数目标值 `target`，请你在该数组中找出和为目标值 `target`  的那两个整数，并返回它们的数组下标。

你可以假设每种输入只会对应一个答案，并且你不能使用两次相同的元素。你可以按任意顺序返回答案。

示例 1：
> 输入：nums = [2,7,11,15], target = 9
> 
> 输出：[0,1]
> 
> 解释：因为 nums[0] + nums[1] == 9 ，返回 [0, 1] 。

示例 2：
> 输入：nums = [3,2,4], target = 6
> 
> 输出：[1,2]

示例 3：
> 输入：nums = [3,3], target = 6
> 
> 输出：[0,1]

提示：
- 2 <= nums.length <= $10^4$
- $-10^9$ <= nums[i] <= $10^9$
- $-10^9$ <= target <= $10^9$
- 只会存在一个有效答案

## 暴力枚举

暴力枚举是这道简单题的一个很直接的思路。从数组的起点开始枚举（设为 `i`），每轮都对其他所有数进行核对，看是否有其他数（设为 `j`）可以满足相加得到 `target`

进一步，当我们枚举第 `i` 个数时，由于索引小于 `i` 的数已经在之前完成枚举了，也就是索引小于 `i` 的数不可能成为答案之一（不然早就得到答案了），所以每轮枚举仅检查索引大于 `i` 的数即可

对于这一种思路，其时间复杂度为 $O(N^2)$，空间复杂度为 $O(1)$

## 哈希检索

我们的目标是找到 `num[i] + num[j] = target`，当我们枚举数 `num[i]` 时，其实就是找是否存在 `num[j]` 满足 `num[j] = target - num[i]`。那么对于查找，很自然想到可以使用哈希进行加速

根据前一种思路，从数组起点开始枚举 `num[i]`，同时将索引大于 `i` 的所有数组元素都放到哈希表中（键为元素大小，值为该数在数组中的索引），并使用键 `target - num[i]` 进行查找即可

该方法还存在优化：我们可以将整个枚举的过程倒过来，也即从数组末尾开始枚举。
1. 首先将最后一个元素添加到哈希表中，并对倒数第二个元素检查是否可以组成答案。此时 `i = N - 2`，仅判断 `j = N - 1` 时是否可以组成答案（最大索引为 `N - 1`）
2. 若失败则将倒数第二个元素添加到哈希表中，并对倒数第三个元素检查是否可以组成答案。此时 `i = N - 3`，判断对 `j = N - 2` 以及 `j = N - 1` 是否可以组成答案
3. 若仍失败则将倒数第三个元素添加到哈希表中，不断迭代直到找到答案获全部枚举完（此时说明没有答案）

原先每次枚举都需要重新建立哈希表，需要 $O(N^2)$ 次插入；而进行优化后可以仅建立一次哈希表，也就是 $O(N)$ 次插入

对于这种思路，时间复杂度为 $O(N)$，空间复杂度为 $O(N)$

代码示例：
```cpp
class Solution {
public:
    vector<int> twoSum(vector<int>& nums, int target) {
        map<int, int> hashMap;
        int len = nums.size();
        hashMap.insert({nums[len - 1], len - 1});
        for (int i = len - 2; i >= 0; i --) {
            int complement = target - nums[i];
            if (hashMap.find(complement) != hashMap.end()) {
                return {i, hashMap[complement]};
            }
            hashMap.insert({nums[i], i});
        }
        return {};
    }
};
```
